# Run の閲覧（リポジトリ詳細・Run 詳細・違反一覧）: 設計

要件は [requirements.md](requirements.md)。画面の共通規則は [アーキテクチャ](../../architecture.md#7-画面の共通規則)。

## 1. API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/v1/repositories/{id}` | リポジトリ、最新の判定済み Run とその指標、最後の完全計測 |
| GET | `/api/v1/runs?repositoryId=` | Run 一覧（新しい順。`limit` / `cursor`） |
| GET | `/api/v1/runs/{runId}` | Run 詳細（カテゴリ別の指標、未計測の指標、違反の件数、処理失敗の内容） |
| GET | `/api/v1/runs/{runId}/findings` | 違反一覧（`metricId` / `state` / `severity` で絞り込み。複数指定可） |
| GET | `/api/v1/runs/{runId}/artifacts` | 取り込んだ成果物の一覧 |
| GET | `/api/v1/runs/{runId}/artifacts/{artifactId}/content` | 成果物のダウンロード |

| 項目 | 設計 |
| --- | --- |
| Run 一覧のカーソル | `(measuredAt, id)` のキーセット。時系列に増え続けるため、オフセットでは送り中に重複・欠落が起きる |
| 違反一覧のページング | 判定時に確定したスナップショットなので、カーソルの中身は位置（オフセット） |
| 違反の並び順 | 状態（新規 → 継続 → 初回 → 解消）→ 深刻度（Critical → High → Medium → Low → Info） |
| 絞り込みの未知の値 | `state` / `severity` に未知の値を渡したら 400 |
| カテゴリ | 指標をカテゴリ（機能テスト・性能・セキュリティ・コード構造・契約・互換性・使いやすさ）にまとめ、カテゴリの判定と初期状態で開くか（不合格・注意を含むか）をサーバが決める |
| 指標の行 | 計測条件の生の値（`variant`）と表示名（`variantLabel`）、前回値と差（条件が一致する比較対象からだけ）を返す |
| ファイルを指さない違反 | M-07〜M-10 の違反はリポジトリ上のファイルでないため、`filePath` / `line` / `sourceUrl` は null。位置は `detail`（ページと CSS セレクタ、テスト名、API のパスなど）で示す |
| GitHub へのリンク | `https://github.com/<owner>/<repo>/blob/<sha>/<path>#L<n>` を組み立てるだけで、API は呼ばない |
| 処理失敗 | `failure` に `errorCode`・詳細・対処（`hint`）を入れる |
| 成果物 | 常に `Content-Disposition: attachment` で返す（ブラウザで開かせない）。実体が削除済みなら `409 ARTIFACTS_DELETED` |

## 2. リポジトリ詳細（S-02）

```
┌───────────────────────────────────────────────────────────────────┐
│ example/sample                          設定  トレンド  リリース判定 │
├─ 最新の判定 ──────────────────────────────────────────────────── │
│ ■ 不合格   main · a1b2c3d · 2026-09-21 02:12 · 部分計測           │
│ 最後の完全計測: 2026-09-20 02:11（Run を見る）                     │
│ 指標                      現在値    しきい値   前回比   判定      │
│ ブランチカバレッジ(back)   82.4%    75% 以上   +0.5     ● 合格    │
│ 重大・高 脆弱性件数        2 件     0 件       +2       ■ 不合格  │
├─ 直近の Run ─────────────────────────────────────────────────── │
│ 2026-09-21 02:12  main  a1b2c3d  ■ 不合格  部分計測               │
│ 2026-09-20 02:11  main  9f8e7d6  ● 合格    完全計測               │
└───────────────────────────────────────────────────────────────────┘
```

- 直近の Run は 10 件。判定済みでない Run は状態（処理失敗は「◆ 処理失敗」）を出す
- 前回比は**差分そのもの**（`+0.5`）で示し、矢印の色に頼らない。「増えて良い」指標（カバレッジ）と「増えて悪い」指標（脆弱性）が同じ表に並ぶため、良し悪しは判定列が担う

## 3. Run 詳細（S-03）

```
┌───────────────────────────────────────────────────────────────────┐
│ Run a1b2c3d   ■ 不合格   部分計測（未計測 1 件）      [再評価]    │
│ main · 2026-09-21 02:12                                           │
│ コミット a1b2c3d ↗ / CI 実行 ↗ / 合格ライン 4c5d6e7                │
│ 比較対象: Run 9f8e7d6                                             │
├───────────────────────────────────────────────────────────────────┤
│ ▼ 機能テスト                                          ● 合格      │
│   ブランチカバレッジ（backend）  82.4%  ≥75%  +0.5  ● 合格        │
│     しきい値 75% を満たしています（実測 82.4%）                    │
│   ミューテーションスコア          —     ≥60%   —    ○ 未計測      │
│ ▼ セキュリティ                                        ■ 不合格    │
│   重大・高 脆弱性件数           2 件   0 件  +2   ■ 不合格        │
│     Critical 1 件、High 1 件が未解決です   [違反を見る →]         │
│ ▶ 性能 / コード構造 / 契約・互換性 / 使いやすさ                   │
├─ 未計測の指標 ─────────────────────────────────────────────────── │
│ ミューテーションスコア（申告あり・受理）                           │
│   収集ランナーは PR の計測ではミューテーションテストを実行しない   │
├───────────────────────────────────────────────────────────────────┤
│ 違反の内訳: 新規 2 ・ 継続 5 ・ 解消 3 ・ 初回 0                   │
│ 取り込んだ成果物: 12 件 [一覧]                                     │
└───────────────────────────────────────────────────────────────────┘
```

| 項目 | 仕様 |
| --- | --- |
| カテゴリ | API の `categories` をそのまま描く。分類の規則を画面に持たない |
| 折りたたみ | 不合格・注意を含むカテゴリは初期状態で開き、それ以外は閉じる。開いた瞬間に問題が見え、問題が他に埋もれない |
| 判定理由 | `reason` をそのまま表示する（文言はサーバが持つ） |
| 計測条件 | 指標名の括弧にコンポーネント名と並べて出す（「応答時間 p95（backend・perf-staging）」） |
| 未計測 | スキップの理由と、受理されたか（「申告あり・受理」/「申告あり・未許容のため計測エラー」）を併記する |
| 指標の限界 | M-08 の行には、判定によらず「自動検査で検出できるのは WCAG 違反の一部で、重大 0 件は適合の必要条件であって十分条件ではない」と注記する |
| 比較対象 | 比較対象 Run へのリンク。無ければ「既存の違反を初回として数えている」ことを示す |
| 再評価 | EVALUATED / FAILED の Run に出す。ADMIN 以外にも見せたうえで無効化し、理由を示す。結果は `aria-live` で知らせる |
| 処理失敗 | 判定表の代わりに、原因（`errorCode` と詳細）と対処を出す。◆「処理失敗」で、不合格の ■ と見た目を分ける |
| 成果物 | 「一覧」で取得し、ファイル名・種別・コンポーネント・大きさを出す。削除済みはリンクにしない |

## 4. 違反一覧（S-04）

```
┌───────────────────────────────────────────────────────────────────┐
│ 違反一覧 — Run a1b2c3d                                            │
│ 状態 [新規][継続][初回][解消]  深刻度 [重大][高][中][低][情報]     │
├───────────────────────────────────────────────────────────────────┤
│ 新規  重大  CVE-2026-1234: example-lib の任意コード実行           │
│       backend/pom.xml · CVSS 8.1 · アドバイザリ ↗ · GitHub で見る ↗ │
│ 継続  高    CVE-2025-9876: another-lib の情報漏洩                 │
└───────────────────────────────────────────────────────────────────┘
```

| 項目 | 仕様 |
| --- | --- |
| 既定の絞り込み | 状態 = 新規・継続・初回（解消は選んだときだけ出す） |
| 指標での絞り込み | Run 詳細の「違反を見る」から指標を指定して開く。解除できる |
| 外部リンク | 新しいタブで開き、リンクに「外部サイト」を示す。脆弱性はアドバイザリ、a11y はルールの解説（axe の `helpUrl`）へのリンクも出す |
| ファイルを持たない違反 | GitHub へのリンクを出さない。a11y は画面と要素、テストはテスト名と失敗理由、破壊的変更は「メソッド パス: 説明」で位置を示す |
| 件数が多いとき | 「さらに読み込む」で続きを取得する |
