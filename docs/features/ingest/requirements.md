# 取り込み（Ingest API）: 要件

収集ランナーが計測した成果物を受け取り、Run として記録して判定につなぐ。設計は [design.md](design.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-01 | 開発者 | 計測プロファイル（`collector/target/profile.env`）とアプリの `QG_REPOSITORY` に対象を書き、計測できるようにする |
| UC-02 | 開発者 | 収集ランナーでブランチ・コミット・タグを指定して計測すると、判定結果が生成される |

## 機能要件

| ID | 要件 |
| --- | --- |
| INGEST-1 | 計測対象は 1 つだけ（`QG_REPOSITORY`）。それと違うリポジトリの計測は拒否する。初めて計測が届いたときにリポジトリを登録する |
| INGEST-2 | 既定ブランチは計測プロファイルの `DEFAULT_BRANCH` とし、計測ごとに送られた値で更新する |
| INGEST-3 | Ingest API で Run を開始し、成果物を添付し、確定（finalize）できる。確定するとその場で判定し、結果を返す |
| INGEST-4 | Run にはコミット SHA、ブランチ、実行者、CI 実行 URL、計測日時、比較元のコミット、コミットを指すタグを付ける |
| INGEST-5 | 性能の成果物には計測環境（環境名など）を必須とする |
| INGEST-6 | 同じコミットへの再送信は既存の Run を上書きせず、新しい試行（attempt）として記録する |
| INGEST-7 | 取り込みの失敗（形式不正、サイズ超過、トークン不正）は理由を構造化して返す。上限は 1 ファイル 50MB、1 Run 200MB |
| INGEST-9 | Ingest API は収集ランナー用の Ingest Token（1 つ）で認証し、書き込み専用とする |

## 受け入れ基準

- 収集ランナーが成果物を送って確定すると、応答で判定結果とリリース判定の URL が返り、画面で判定を確認できる
- 成果物を未提出にすると、その指標が ERROR になり Run 全体が FAIL になる
- 必須のメタデータ（性能の `environment`）が無い成果物は、取り込みの時点で理由つきで拒否される
- Ingest Token では参照 API を呼べない
