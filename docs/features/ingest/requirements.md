# 取り込み（Ingest API）: 要件

収集ランナーが計測した成果物を受け取り、Run として記録して判定につなぐ。設計は [design.md](design.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-01 | Admin | `collector/targets/` に計測プロファイルと合格ラインを追加し、対象を計測できるようにする（quality-gate での登録操作は無い） |
| UC-02 | Admin | 収集ランナーでブランチ・コミット・タグ・PR を指定して計測すると、判定結果が生成される |

## 機能要件

| ID | 要件 |
| --- | --- |
| INGEST-1 | 計測対象は計測プロファイル（`collector/targets/<owner>__<name>.env`）で決める。バックエンドは初めて計測が届いたリポジトリを登録する |
| INGEST-2 | 既定ブランチは計測プロファイルの `DEFAULT_BRANCH` とし、計測ごとに送られた値で更新する。トレンドの既定の系列に使う |
| INGEST-3 | Ingest API で Run を開始し、成果物を添付し、確定（finalize）できる。確定するとその場で判定し、結果を返す |
| INGEST-4 | Run にはコミット SHA、ブランチ、PR 番号、実行者、CI 実行 URL、計測日時、比較元のコミット、コミットを指すタグ、合格ラインを送った quality-gate のコミットを付ける |
| INGEST-5 | 性能の成果物には計測環境（環境名など）を必須とする |
| INGEST-6 | 同じコミットへの再送信は既存の Run を上書きせず、新しい試行（attempt）として記録する |
| INGEST-7 | 取り込みの失敗（形式不正、サイズ超過、トークン不正）は理由を構造化して返す。上限は 1 ファイル 50MB、1 Run 200MB |
| INGEST-8 | 実行しなかった指標を `skippedMetrics`（指標 ID と理由）として申告できる |
| INGEST-9 | Ingest API は収集ランナー用の Ingest Token（1 つ）で認証し、書き込み専用とする |

## 受け入れ基準

- 収集ランナーが成果物を送って確定すると、応答で判定結果が返り、Run 詳細で判定を確認できる
- 成果物を未提出にすると、その指標が ERROR になり Run 全体が FAIL になる
- 必須のメタデータ（性能の `environment`）が無い成果物は、取り込みの時点で理由つきで拒否される
- Ingest Token では参照 API を呼べない
