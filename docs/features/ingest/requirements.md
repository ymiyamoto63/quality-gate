# 取り込み（Ingest API）: 要件

収集ランナーが計測した成果物を受け取り、Run として記録して判定につなぐ。設計は [design.md](design.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-01 | 開発者 | 計測プロファイル（`collector/targets/<名前>/profile.env`）を用意し、アプリの `QG_REPOSITORY` で対象を選び（同じリポジトリの計測プロファイルが使われる）、計測できるようにする |
| UC-02 | 開発者 | 収集ランナーでブランチ・コミット・タグを指定して計測すると、判定結果が生成される |

## 機能要件

| ID | 要件 |
| --- | --- |
| INGEST-1 | 計測対象は 1 つだけ（`QG_REPOSITORY`）。それと違うリポジトリの計測は拒否する。初めて計測が届いたときにリポジトリを登録する |
| INGEST-3 | Ingest API で Run を開始し、成果物を添付し、確定（finalize）できる。確定するとその場で判定し、結果を返す |
| INGEST-4 | Run にはコミット SHA、ブランチ、CI 実行 URL、計測日時、比較元のコミット、コミットを指すタグを付ける |
| INGEST-11 | Run の作成時に、成果物を送るコンポーネント（計測プロファイルの `BACKEND_DIR` / `FRONTEND_DIR` の名前）の申告を必須とする。申告に無いコンポーネントの成果物は拒否する |
| INGEST-5 | 性能の成果物には計測環境（環境名など）を必須とする |
| INGEST-6 | 同じコミットへの再送信は既存の Run を上書きせず、新しい試行（attempt）として記録する |
| INGEST-7 | 取り込みの失敗（入力の不正、未知の種別、メタデータの不足、サイズ超過）は理由を構造化して返す（トークンの不正は本文なしの 401）。上限は 1 ファイル 50MB、1 Run 200MB |
| INGEST-9 | Ingest API は収集ランナー用の Ingest Token（1 つ）で認証し、書き込み専用とする（読めるのは INGEST-10 の設定だけ） |
| INGEST-10 | 収集ランナーは計測の前にアプリの設定（計測対象のリポジトリ、`QG_DISABLED_METRICS`、`QG_ACCESSIBILITY_PAGES`）を読み、判定しない指標は計測せず、M-08 で検査されているべき画面を検査する |

## 受け入れ基準

- 収集ランナーが成果物を送って確定すると、応答で判定結果とリリース判定の URL が返り、画面で判定を確認できる
- 成果物を未提出にすると、その指標が ERROR になり Run 全体が FAIL になる
- backend と frontend を申告して backend の成果物だけを送ると、M-01 / M-09 / M-10 の frontend が ERROR になり Run 全体が FAIL になる
- 申告していないコンポーネントを付けた成果物は、取り込みの時点で `422 COMPONENT_NOT_DECLARED` で拒否される
- 必須のメタデータ（性能の `environment`）が無い成果物は、取り込みの時点で理由つきで拒否される
- Ingest Token では参照 API を呼べない
- アプリの `QG_DISABLED_METRICS` に書いた指標は、計測プロファイルを変えなくても次の計測から計測されない
- アプリの `QG_ACCESSIBILITY_PAGES` に画面を足すと、計測プロファイルを変えなくても次の計測からその画面が検査される（パターンを除く）
