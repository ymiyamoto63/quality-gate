# リリース判定: 要件

タグかコミットを指定すると、リリースしてよいかを指標ごとの合否と根拠を添えて 1 画面で示し、証跡（CSV）を残す（S-08）。設計は [design.md](design.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-06 | 全員 | リリース判定会議で、タグかコミットを指定して結論と全指標の合否を確認し、CSV を証跡として残す |

## 機能要件

| ID | 要件 |
| --- | --- |
| REL-1 | タグかコミットを指定して、そのコミットで判定済みの Run から、リリースの可否（リリース可 / リリース可（注意あり）/ リリース不可 / 判定できない）と全指標の合否を 1 画面に示す |
| REL-2 | 使うのは同じコミットの最新の完全計測で、近くのコミットでは代用しない。未計測、または部分計測で不合格が無ければ「判定できない」 |
| REL-3 | 指標ごとに「何を見るか」「基準の根拠」「満たさないと何が起きるか」を、開発に詳しくない人にも分かる言葉で示す。根拠には種類（外部基準 / 業界の目安 / チーム判断）を付ける |
| REL-4 | CSV（1 行 1 指標。判定の前提・出力日時・出力者を各行に含む）で出力でき、印刷して PDF にもできる。CSV の出力は監査ログに残す |
| REL-5 | 判定の前提（比較元のコミット、合格ラインを送った quality-gate のコミット、除外パターンなど）を示す。タグで計測したときの比較元は前のタグ |

## 受け入れ基準

- タグを指定して計測すると、リリース判定でそのタグから結論と全指標の合否を表示でき、CSV を出力できる
- PR の計測（部分計測）しか無いコミットは、不合格が無ければ「判定できない」になる
- 同じ指定で何度開いても、結論が変わらない（Run の判定時の結果をそのまま使う）
- リリース判定会議で、タグを指定するだけで結論と根拠を示せる（計測から表示・CSV の出力まで追加の作業が要らない）
