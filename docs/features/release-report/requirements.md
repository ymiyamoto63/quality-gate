# リリース判定: 要件

品質基準に照らしてリリースしてよいかを、開発に携わっていない方を含め、誰にでもひと目で分かる形で 1 画面に示す。結論を示す画面はこれ 1 つだけ（指標の推移は補助の画面。[指標の推移](../trends/requirements.md)）。設計は [design.md](design.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-03 | リリース判断者・開発者 | リリース判定会議で、最新の計測（またはタグ・コミット）の結論と全指標の合否を確認し、印刷（PDF）して証跡として残す |
| UC-04 | リリース判断者 | 判定の履歴で、過去のリリースが品質基準をクリアしてきたかを確認する |
| UC-05 | 開発者 | リリース不可のとき、どの指標のどこ（関数・CVE・画面など）を直せばよいかを確かめる |

## 機能要件

| ID | 要件 |
| --- | --- |
| REL-1 | 結論（リリース可 / リリース不可 / 未計測）と全指標の合否を 1 画面に示す。使う計測は、指定が無ければ判定を終えた最新の計測、タグかコミットを指定すればそのコミットで判定を終えた最新の計測 |
| REL-2 | 指標の合否は合格 / 不合格の 2 値。計測エラーは不合格として扱う。近くのコミットの計測では代用しない |
| REL-3 | 指標ごとに「何を見るか」「合格ライン」「結果」を並べ、「基準の根拠」「満たさないと何が起きるか」を専門用語に頼らない言葉で示す。根拠には種類（外部基準 / 業界の目安 / チーム判断）を付ける |
| REL-4 | 不合格の指標には理由と主な違反（深刻な順に最大 10 件、GitHub の該当箇所へのリンク）を示す |
| REL-5 | 判定の履歴（新しい順、同じコミットは最後の判定だけ）を示し、そこから各判定を開ける |
| REL-6 | 印刷して PDF にできる（CSV の出力は持たない） |
| REL-7 | 判定の対象外にした指標（設定で判定から外した指標と、ツールの制約などで対象外の結果）を、結論のすぐ下と結論の理由に理由つきで示す。合否の件数と結論には数えない |
| REL-8 | 合格ラインを既定値より緩めて判定した指標には、その印と既定の合格ラインを示す。`QG_EXCLUSIONS` でファイルを計測から外した指標（M-01 / M-02 / M-05 / M-06 / M-11 / M-12）には、外したファイルの数を示す |
| REL-9 | 判定の範囲を狭めていた設定（計測除外のパターン、M-02 の対象コンポーネントの限定、M-03 のシナリオ・M-08 の画面の指定が無いこと）を、判定したときの値のまま「判定の条件」として結論の下に示す。条件を記録する前の計測では「記録なし」と示す |
| REL-10 | 判定の履歴の各行に、判定した項目の数と対象外の項目の数、既定より緩めた合格ラインや計測から外したファイルの有無を示す。外した指標のある合格と、すべての指標での合格を見分けられるようにする |

## 受け入れ基準

- 画面を開くと、最新の計測の結論が最上部に大きく出る
- タグを指定して計測すると、そのタグを入れる（または履歴から選ぶ）だけで結論と根拠を示せる
- 同じ指定で何度開いても、結論が変わらない（Run の判定時の結果をそのまま使う。合格ラインの環境変数を後から変えても変わらない）
- 計測していないコミットは「未計測」になり、合格とはみなさない
- `QG_DISABLED_METRICS=M-03,M-04` で判定すると、結論の理由に「（2 件は判定の対象外です: 応答時間 p95、エラー率）」と出て、結論の下に 2 つの指標と理由が並ぶ。後から設定を変えても、その判定の表示は変わらない
- `QG_BRANCH_COVERAGE_MIN=70` で判定すると、M-01 の行に「既定より緩い（既定 ≥ 75%）」と出る
- `QG_EXCLUSIONS=config.py` で、`config.py` にだけシークレットのある計測を判定すると、M-11 は合格のまま理由に「QG_EXCLUSIONS で検査から外した 1 ファイルに検出があり、件数に含めていません」と出て、行に「1 ファイルを計測から除外」、結論の下の「判定の条件」に除外パターンが出る
- `QG_DISABLED_METRICS` で 10 の指標を外した合格は、履歴で「2 項目を判定（10 項目は対象外）」と出て、すべての指標での合格と見分けられる
