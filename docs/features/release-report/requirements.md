# リリース判定: 要件

品質基準に照らしてリリースしてよいかを、開発に携わっていない方を含め、誰にでもひと目で分かる形で 1 画面に示す。アプリの画面はこれ 1 つだけ。設計は [design.md](design.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-06 | リリース判断者・開発者 | リリース判定会議で、最新の計測（またはタグ・コミット）の結論と全指標の合否を確認し、印刷（PDF）して証跡として残す |
| UC-07 | リリース判断者 | 判定の履歴で、過去のリリースが品質基準をクリアしてきたかを確認する |
| UC-08 | 開発者 | リリース不可のとき、どの指標のどこ（関数・CVE・画面など）を直せばよいかを確かめる |

## 機能要件

| ID | 要件 |
| --- | --- |
| REL-1 | 指定が無ければ最新の判定済みの計測、タグかコミットを指定すればそのコミットの最新の判定済みの計測から、結論（リリース可 / リリース不可 / 未計測）と全指標の合否を 1 画面に示す |
| REL-2 | 指標の合否は合格 / 不合格の 2 値。計測エラーは不合格として扱う。近くのコミットの計測では代用しない |
| REL-3 | 指標ごとに「何を見るか」「合格ライン」「結果」を並べ、「基準の根拠」「満たさないと何が起きるか」を専門用語に頼らない言葉で示す。根拠には種類（外部基準 / 業界の目安 / チーム判断）を付ける |
| REL-4 | 不合格の指標には理由と主な違反（深刻な順に最大 10 件、GitHub の該当箇所へのリンク）を示す |
| REL-5 | 判定の履歴（新しい順、同じコミットは最後の判定だけ）を示し、そこから各判定を開ける |
| REL-6 | 印刷して PDF にできる（CSV の出力は持たない） |

## 受け入れ基準

- 画面を開くと、最新の計測の結論が最上部に大きく出る
- タグを指定して計測すると、そのタグを入れる（または履歴から選ぶ）だけで結論と根拠を示せる
- 同じ指定で何度開いても、結論が変わらない（Run の判定時の結果をそのまま使う。合格ラインの環境変数を後から変えても変わらない）
- 計測していないコミットは「未計測」になり、合格とはみなさない
