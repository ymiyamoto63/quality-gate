# リリース判定: 設計

要件は [requirements.md](requirements.md)。リリースのための計測の手順は [運用](../../operations.md#52-リリース判定のために計測する)。

## 1. 指定（`ref`）の解決

| 指定 | 解決 |
| --- | --- |
| 16 進 7〜40 桁 | コミット SHA とみなし、計測済みの Run から前方一致で探す（複数一致は 400） |
| それ以外 | タグとみなし、収集ランナーが計測時に送ったタグ（Run の `tags`）からコミットを探す。git のタグ名に使えない文字は 400 |

- **ブランチ名は受け付けない**。先頭が時間とともに動くため証跡にならない
- GitHub API は使わない（DD-10）。そのため、**タグを付ける前に計測したコミットはタグで見つからない**（タグを付けて計測し直すか、コミット SHA で指定する）
- 未計測でも 200 で返す（結論は「判定できない」）

## 2. 結論の決め方

同じコミットの判定済みの Run のうち、最新の完全計測を使う。完全計測が無ければ最新の Run を使う。判定し直さず、Run の判定時の結果をそのまま使う（見るたびに結論が変わると証跡にならない）。

| 順 | 条件 | 結論 |
| --- | --- | --- |
| 1 | 判定済みの Run が無い | 判定できない（`UNDETERMINED`） |
| 2 | 不合格（FAIL）または計測エラー（ERROR）の指標がある | リリース不可（`NOT_RELEASABLE`）。部分計測でも、測った範囲に不合格があれば確定する |
| 3 | 部分計測 | 判定できない（`UNDETERMINED`）。測っていない指標を合格とみなさない |
| 4 | 注意（WARN）の指標がある | リリース可（注意あり）（`RELEASABLE_WITH_WARNINGS`） |
| 5 | それ以外 | リリース可（`RELEASABLE`） |

前回のリリースとの比較、承認の仕組み、総合点は持たない。

## 3. API

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/v1/repositories/{id}/release-report?ref=` | 結論・理由・前提・指標ごとの合否・各指標の説明と根拠 |
| GET | `/api/v1/repositories/{id}/release-report.csv?ref=` | CSV。出力を監査ログ（`RELEASE_REPORT_EXPORTED`）に残す |

**CSV**

- 1 行 1 指標。列は「リポジトリ・指定・コミット・リリース判定・判定の理由・Run ID・計測日時・計測範囲・比較元コミット・合格ラインのコミット・除外パターン・指標ID・指標・カテゴリ・コンポーネント・計測条件・値・しきい値・判定・判定の詳細・何を見る指標か・根拠の種類・基準の根拠・計測ツール・出力日時・出力者」
- 読み手に経営陣を想定するため、列名と値は日本語にする。Excel で開けるよう UTF-8 の BOM を付ける
- 出力日時は `QG_SCHEDULE_ZONE`（既定 `Asia/Tokyo`）で書く
- `=` `+` `-` `@` などで始まる値は先頭に `'` を付け、表計算ソフトで数式として実行されないようにする（CSV インジェクション対策）

**指標の説明と根拠**は `MetricGuide` が持つ。根拠の種類は次の 3 つで、チームで決めた値を外部の基準と同じ口調で書かない。

| 種類 | 指標 |
| --- | --- |
| 外部基準 | M-05（CVSS）・M-06（McCabe の複雑度）・M-08（WCAG 2.2 AA） |
| 業界の目安 | M-01 |
| チーム判断 | M-02・M-03・M-04・M-07・M-09〜M-12 |

根拠の文は既定の基準についての説明で、基準を変えた場合の理由は合格ラインのコミットに残る（画面にその旨を書く）。

## 4. 画面（S-08）

リポジトリ詳細の「リリース判定」から開く。タグかコミット SHA を入れて「判定する」。指定は URL の `?ref=` に置き、同じ判定を URL で共有できる。
読み手に経営陣や開発に詳しくない人を想定し、**結論 → 指標ごとの合否 → 各指標の説明と根拠**の順に並べる。結論と表の 3 列（指標・基準・判定）だけ読めば足りるようにする。

| 領域 | 内容 |
| --- | --- |
| 結論 | 「リリース可」「リリース可（注意あり）」「リリース不可」「判定できない」を見出しにし、理由を 1 文で添える。左端の帯の色は補助で、文言とチップの記号でも分かるようにする |
| 前提 | タグ、コミット（GitHub へのリンク）、計測日時（Run 詳細へのリンク）と完全 / 部分計測、比較元のコミット、合格ラインを送った quality-gate のコミット（無ければ「既定値」）、計測から除外したパス、同じコミットのほかの計測の件数 |
| 指標ごとの合否 | 合否に使う指標の件数の内訳と、指標・何を見るか・基準・結果・判定の表。問題のある指標を先に並べる |
| 説明と根拠 | 指標ごとに「何を見るか」「基準の根拠」「基準を満たさないと」「計測ツール」と根拠の種類。技術的な定義は「技術的な定義」を開いたときだけ見せる |
| CSV | 「CSV をダウンロード（証跡）」 |
| PDF | 「PDF として保存（印刷）」。ブラウザの印刷を使い、印刷では入力欄と操作部品を隠す |

説明文は開発者以外も読むため、専門用語は括弧で補い、1 文を短くする。
