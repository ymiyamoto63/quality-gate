# リリース判定: 設計

要件は [requirements.md](requirements.md)。

## 1. API

| メソッド | パス | 応答 |
| --- | --- | --- |
| GET | `/api/v1/release?ref=` | `ReleaseReportResponse`。`ref` を省くと最新の判定済みの計測 |
| GET | `/api/v1/release/history` | `ReleaseHistoryResponse`（最大 50 件） |

対象は `QG_REPOSITORY` の 1 つだけのため、パスにリポジトリを含めない。

## 2. 指定の解決（`ReleaseRefResolver`）

- 16 進数 7〜40 桁はコミット SHA とみなし、計測済みのコミットから前方一致で探す（複数に一致すれば 400）
- それ以外はタグ名とみなし、収集ランナーが計測時に送ったタグ（`runs.tags`）から探す。無ければ 404（タグを付ける前に計測したコミットはタグで引けない。DD-11）
- ブランチ名は受け付けない。ブランチの先頭は時間とともに動くため、証跡にならない

## 3. 結論

| 結論 | 条件 |
| --- | --- |
| `RELEASABLE`（リリース可） | 判定済みの Run の verdict が `PASS` |
| `NOT_RELEASABLE`（リリース不可） | verdict が `FAIL`（不合格か計測エラーの指標がある） |
| `NOT_MEASURED`（未計測） | そのコミットの判定済みの Run が無い（計測していない、または処理失敗だけ） |

- 使う Run は、そのコミットで判定を終えた最新の attempt。判定し直さない（見るたびに結論が変わると証跡にならない）
- 理由の文言（`decisionReason`）はサーバが組み立て、画面はそのまま出す。判定の対象外があれば必ず名前を添える（「判定した 10 件の指標が、すべて合格ラインを満たしています（2 件は判定の対象外です: 応答時間 p95、エラー率）。」。リリース不可なら「ほかに 2 件は判定の対象外です（…）。」）
- 対象外（`NOT_APPLICABLE`）の結果は合否に使わないため、`metrics` と件数（`counts`）に含めず、`notJudged` に出す

## 3.1 判定の対象外（`notJudged`）

「すべて合格」が何についての結論かを示す（DD-27）。指標の一覧の並びで、次の 2 つを並べる。

| 種類 | 出どころ | `reason` |
| --- | --- | --- |
| 設定で判定から外した指標 | 判定時に Run に焼き付けた `runs.disabled_metrics`（今の設定は読まない。後から変えても過去の判定の範囲が変わらないように） | 「設定（QG_DISABLED_METRICS）で判定から外しています」 |
| 対象外の結果 | `status = NOT_APPLICABLE` の `measurements`（M-02 の frontend、比較元に定義の無い M-07 など） | 保存した判定理由 |

`runs.disabled_metrics` の無い Run（V003 より前に判定したもの）は、外した指標が分からないため「無し」として扱う（対象外の結果だけを出す）。

## 4. 指標の行

| 項目 | 内容 |
| --- | --- |
| 並び | 不合格・計測エラーを先に、その中は指標 ID の順 |
| 合格ライン | 判定に使った `measurements.threshold` を「≥ 75%」「≤ 0 件」「前回から +0 件以内」（M-10）のような文字列にする |
| 既定より緩い | 判定時に記録した印（`threshold` の `relaxed`）を `thresholdRelaxed` に、既定の合格ライン（`default`）を `defaultThreshold`（「≥ 75%」、補足が緩いときは「関数ごとの循環的複雑度の上限 15」）に返す。印の無い過去の行は緩くないものとして扱う。指標の推移の点（`TrendPoint`）も同じ 2 項目を返す |
| 除外したファイル | 内訳（`detail`）の `excludedFiles`（M-01 / M-02）を `excludedFileCount` に返す。無ければ 0 |
| 主な違反 | 合格でない行だけ。解消済みを除いた違反を、同じ指標（とコンポーネント）で絞り、深刻な順に最大 10 件。`findingCount` に総数を返す。ファイルと行があれば GitHub の該当箇所の URL を付ける |
| 説明 | 結果に現れた指標ごとに `MetricGuide`（何を見るか・根拠の種類と理由・満たさないと何が起きるか・技術的な定義・計測ツール） |

## 5. 画面（`/`）

上から次の順に並べる。

1. 結論（大きな見出し。色だけに頼らず、記号とアイコンと文言で示す）、理由、「品質基準 N 項目のうち M 項目が合格」、判定の対象外（枠で囲み、指標と理由を並べる。印刷にも含める）、既定より緩めた合格ラインの件数、タグ・コミット・計測日時（計測のログへのリンク）・比較元
2. 品質基準ごとの合否（判定・指標・何を見るか・合格ライン・結果。合格ラインの下に「既定より緩い（既定 ≥ 75%）」「N ファイルを計測から除外（QG_EXCLUSIONS）」の印。不合格の行には理由と、開ける「主な違反」）
3. 各指標の説明と基準の根拠
4. 判定の履歴（印刷には含めない。[指標の推移](../trends/design.md) へのリンクを添える）

- 指定は `?ref=` に置き、URL で同じ判定を共有できる
- 「PDF として保存（印刷）」はブラウザの印刷を使う。ヘッダ・入力欄・履歴は印刷しない
- 印は色ではなく記号（アイコンは装飾として読み上げから外す）と文言で示し、文字色は本文のまま（[アーキテクチャ 7.3](../../architecture.md#73-ステータスの表現)）
- アクセシビリティは [アーキテクチャ](../../architecture.md#77-アクセシビリティ) に従い、リリース不可の状態（主な違反を開き、判定の対象外と既定より緩い印のある状態）で自動検査する
