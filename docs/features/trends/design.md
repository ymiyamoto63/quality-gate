# トレンド: 設計

要件は [requirements.md](requirements.md)。画面の共通規則は [アーキテクチャ](../../architecture.md#7-画面の共通規則)。

## 1. API

`GET /api/v1/repositories/{id}/trends?metricId=M-01&branch=&from=&to=`

| パラメータ | 既定 |
| --- | --- |
| `metricId` | 必須 |
| `branch` | リポジトリの既定ブランチ |
| `from` / `to` | `to` は現在、`from` は `to` の 30 日前。期間が 730 日を超えたら 400 |

| 設計 | 理由 |
| --- | --- |
| 系列の分割はサーバが行う。コンポーネントと計測条件（`variant`）ごとに 1 系列 | どの計測が同じ条件で比べられるかは指標の性質に属する判断で、画面が決めるものではない |
| コンポーネントや条件を持たない点（未提出の ERROR、SKIP）は、既存の系列に欠測（値 null）として配る。系列が 1 つも無い指標では、そのまま単一の系列になる | 欠測が「もう 1 本の線」として現れないようにする |
| `NOT_APPLICABLE` の点と、判定済みでない Run は返さない | 測りようのないものは推移ではない |
| 系列の色は `colorIndex`（0〜2）としてサーバが固定する | 絞り込みで系列が減っても色が塗り替わらない。検証済みの配色は 3 色で、色を増やして系列を増やさない |
| 期間内にしきい値が変わっていれば `thresholdChanged` で示す | 線は現在の基準で引き、変わったことを文で示す |

`measurements` の `(repository_id, metric_id, measured_at)` の複合インデックス（`ix_measurements_trend`）で、結合なしに範囲を引く。

## 2. 画面（S-05）

```
┌───────────────────────────────────────────────────────────────────┐
│ トレンド  [指標: ブランチカバレッジ ▾] [期間: 直近 30 日 ▾]        │
│ ブランチ: main                                                    │
├───────────────────────────────────────────────────────────────────┤
│  %                                                                │
│ 90│        ●────●                  ●───● backend 84.2              │
│ 80│   ●───╱      ╲     ○         ╱                                 │
│ 75│- - - - - - - - - - - - - - - - - - - - - - - しきい値 75%      │
│ 70│  ●────●────●───●  （未計測）  ●───● frontend 78.1             │
│   └──────────────────────────────────────────────────────         │
│     9/1      9/8      9/15     9/22                               │
│ ● backend  ● frontend                                             │
│ ▸ 表形式で見る（24 件）                                            │
└───────────────────────────────────────────────────────────────────┘
```

| 項目 | 仕様 |
| --- | --- |
| 選べる指標 | M-01〜M-12。M-03 / M-04 は計測環境ごと、M-02 は実行範囲ごとの系列になる |
| 期間 | 直近 30 日 / 90 日 / 1 年 |
| ブランチ | リポジトリの既定ブランチ（画面では選べない） |
| しきい値 | `--text-muted` の破線と直接ラベル。status 色は使わない（点の判定色と競合し、基準の近くの合格の点まで危険に見えるため） |
| 欠測 | 線を切って描く。前後をつなぐと計測していない期間に値があったように見え、0 を打つと最悪の値に落ちたように見える。前後が欠測の点はマーカーだけで描く |
| 不合格の点 | マーカーを大きくし、`--status-fail` のリングと値のラベルを付ける |
| y 軸 | しきい値を必ず範囲に含める。割合は 0 起点にしない（75〜95% の変化が潰れる）。件数は 0 を含める。目盛りはきりのよい数で 7 本以内 |
| 直接ラベル | 系列の最後の点にだけ置き、面の色で縁取る（`paint-order: stroke`） |
| 当たり判定 | マーカー（r=4）より大きい透明な円（r=12）で取り、ツールチップに日時・値・判定・Run へのリンクを出す |
| 凡例 | 常に表示する |
| 表形式 | 「表形式で見る」を開くと同じ値を表で出す（値を読みたい・コピーしたいため。SVG 自体も読み上げられる） |

## 3. 描画の方式

グラフは**インライン SVG** で描く（`TrendChart.vue`。座標の計算は `trendGeometry.ts`）。
canvas は描いた内容をスクリーンリーダーで読めない。SVG なら要素にラベルを付けられ、配色トークンとダークモードに CSS だけで追従し、DOM として検証できる。
1〜3 系列・数十点の密度ではグラフライブラリの機能は要らない。足りなくなれば ECharts を検討する（描画は `TrendChart.vue` に閉じてある）。
