# 指標の推移: 設計

要件は [requirements.md](requirements.md)。

## 1. API

| メソッド | パス | 応答 |
| --- | --- | --- |
| GET | `/api/v1/release/trends` | `MetricTrendResponse`。全指標分を 1 回で返す |

- `runs`: 横軸に並べる計測（古い順）。計測日時・コミット・タグ・Run の合否と、リリース判定を開くときの指定（`ref`。タグがあればタグ、無ければコミット SHA）
- `metrics`: 期間内に一度でも判定した指標（`MetricCatalog` の順）。名前・何を見るか・単位・縦軸の上端（`axisMax`）と、コンポーネント・計測条件ごとの線（`series`）
- 点（`points`）は `runIndex` で `runs` の位置を指す。その指標を判定していない計測には点を置かない。点は合否・値・判定に使った合格ラインの値（`thresholdValue`）と表示用の文字列（`threshold`）を持つ

計測は最大 50 件、指標は 12 なので、点は多くても千件程度に収まる。指標ごとに分けて呼ぶ必要はない。

## 2. 計測の選び方

判定の履歴と同じ `EvaluatedRuns.latestPerCommit` を使う。2 つの画面で数え方がずれると、履歴にある計測が推移に無い（またはその逆）ことになるため、選び方を 1 箇所に置く。

## 3. 値と合格ライン

| 項目 | 内容 |
| --- | --- |
| 値 | `measurements.value` をそのまま返す。計測エラー・対象外は null |
| 合格ライン | `measurements.threshold`（判定時に焼き付けた値）の `value`。`basis` が `increase`（M-10）のものは値の軸に引けないため null |
| 単位 | 最新の計測の `unit` |
| 縦軸の上端 | 単位が `percent` の指標は 100。エラー率（M-04）は合格ラインが 0.1% で、0〜100 では線が底に張りつくため固定しない |
| 線の並び | コンポーネント名、計測条件の順 |

## 4. 画面（`/trends`）

- ヘッダから「リリース判定」「指標の推移」を切り替える。リリース判定の履歴の欄からもリンクする
- グラフは自前の SVG で描く（点は最大 50、要るのは折れ線と合格ラインの線だけで、ライブラリを足すほどの機能は要らない）。描く幅は表示する幅に合わせ、文字の大きさを保つ
- 線の色は `tokens.css` の検証済みの系列色（3 色）を順に使い、線の種類（実線・破線・点線）と凡例でも区別する。4 本目からは色を作らず、控えめな色と線の種類で分ける
- 点はステータスの表現（[アーキテクチャ 7.3](../../architecture.md#73-ステータスの表現)）に合わせ、● 合格 / ■ 不合格 / ◆ 計測エラー / — 対象外の形とステータス色で描く
- 点はリンク（`/?ref=`）で、キーボードでも選べる。マウスを乗せるかフォーカスすると、値・合否・合格ライン・タグかコミット・計測日時をツールチップで示し、同じ内容を `aria-label` に持つ
- 縦軸の目盛りは 1・2・2.5・5 の 10 のべき乗倍で刻む。件数の指標は整数で刻み、ずっと 0 件でも上端は 1 件にする
- 横軸のラベルはタグ（無ければコミットの先頭 7 桁）。重ならないよう幅に応じて間引き、最初と最後の計測は必ず出す
- 各グラフに、同じデータの表（新しい順）を折りたたみで添える
- 印刷ではヘッダ・操作ボタン・ツールチップを出さず、グラフの途中で改ページしない
- アクセシビリティは [アーキテクチャ](../../architecture.md#77-アクセシビリティ) に従い、表を開き、点にフォーカスしてツールチップを出した状態で、ライト / ダークの両方を自動検査する
