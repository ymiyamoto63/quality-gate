# 指標の推移: 要件

指標の値が計測をまたいでどう動いてきたかを、指標ごとのグラフで示す。リリースしてよいかの結論は [リリース判定](../release-report/requirements.md) が示し、この画面はその補助にとどめる。設計は [design.md](design.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-06 | 開発者・リリース判断者 | 開発者は、合格ラインの内側でも値がじわじわ悪くなっていないかに早めに気づく。リリース判断者は、品質基準を守れてきたこと（件数が 0 件のままであることなど）を会議で説明する |

## 機能要件

| ID | 要件 |
| --- | --- |
| TRD-1 | 判定の履歴と同じ数え方の計測（判定を終えたものを新しいものから最大 50 件、同じコミットは最後の判定だけ、ブランチでは絞らない）を、古い順に等間隔で横軸に並べる |
| TRD-2 | 期間内に一度でも判定した指標を、リリース判定と同じ指標 ID の順に、1 指標 1 グラフで並べる。コンポーネント・計測条件で分かれる指標は線を分ける |
| TRD-3 | 点の合否と合格ラインは、それぞれの計測の判定時の値をそのまま使う（判定し直さない）。合格ラインは計測ごとの値で階段状に引く。前回からの増加で判定する指標（M-10）には線を引かない |
| TRD-4 | 縦軸は 0 から始める。% の指標は 0〜100% に固定する。ただしエラー率（M-04）と、% 以外の指標は値と合格ラインから上端を決める |
| TRD-5 | 計測エラー・対象外の点は値を持たないため横軸の上に記号だけを置き、線を途切れさせる |
| TRD-6 | 点を選ぶと、その計測のリリース判定を開く。点の値・合否・合格ライン・タグかコミット・計測日時は、マウスでもキーボードでも確かめられる |
| TRD-7 | 各グラフに同じデータの表を添える。印刷して PDF にできる |

## 受け入れ基準

- 合格ラインを途中で変えても、過去の点の合否と合格ラインの段は当時の値のまま示される
- 判定の履歴に出る計測と、推移の横軸に並ぶ計測が一致する
- 計測エラーの計測をまたいで線がつながらない
- 色が見分けにくい人やモノクロ印刷でも、線は線の種類と凡例で、点は記号で見分けられる
