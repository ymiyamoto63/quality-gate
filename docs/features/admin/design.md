# 管理（利用者と監査ログ）: 設計

要件は [requirements.md](requirements.md)。ログインと許可リストの照合は [認証](../auth/design.md)。

## 1. API（すべて ADMIN）

| メソッド | パス | 内容 |
| --- | --- | --- |
| GET | `/api/v1/users` | 利用者の一覧 |
| POST | `/api/v1/users` | 利用者の追加（GitHub のログイン名とロール） |
| PATCH | `/api/v1/users/{id}` | ロール・状態の変更 |
| GET | `/api/v1/audit-logs` | 監査ログ（`from` / `to` / `action` で絞り込み、カーソルでページング） |

| 設計 | 理由 |
| --- | --- |
| 自分自身の降格・無効化と、有効な管理者が 0 人になる変更は `409 ADMIN_REQUIRED` | 誰も管理操作をできなくなるのを防ぐ。画面でも同じ制御をするが、防御は API が担う |
| 同じログイン名の利用者は `409 USER_ALREADY_EXISTS` | |
| GitHub のユーザーの実在は確認しない | 外部の障害に巻き込まれないため。存在しない名前はログインできないだけ |

## 2. 監査ログ

| 操作（`action`） | 記録するとき |
| --- | --- |
| `BOOTSTRAP_ADMIN` | 利用者が 0 人の状態で、最初のログイン利用者を管理者にした |
| `USER_ADDED` / `USER_ROLE_CHANGED` / `USER_STATUS_CHANGED` | 許可リストへの追加、ロールの変更、有効・無効の変更 |
| `RUN_REEVALUATION_REQUESTED` | 再評価を依頼した（判定に失敗しても、誰が依頼したかは残る） |
| `RELEASE_REPORT_EXPORTED` | リリース判定の CSV を出力した（証跡として、いつ誰が出したかを残す） |

- 日時・実行者・操作・対象・変更内容を記録する
- **追記のみ**。DB にロール `quality_gate_app` があれば、マイグレーションが `audit_logs` の `UPDATE` / `DELETE` を剥奪する（アプリ側の実装ミスで改変させない）
- 保持期間（既定 2 年）を過ぎた行は日次バッチが消す。アプリのロールに削除権限が無ければ警告を出して何もしないため、管理用のロールのバッチで消す（[保持期間](../retention/design.md)）

## 3. 画面（S-07）

タブごとに URL を分ける（`/admin/users`・`/admin/audit-logs`）。ヘッダの「管理」は ADMIN にだけ出す。

| タブ | 内容 |
| --- | --- |
| 利用者 | GitHub ログイン名、ロール、状態、最終ログイン。追加・ロール変更・無効化。自分自身の行は変更の操作を無効化し、理由を示す |
| 監査ログ | 日時・実行者・操作・対象・変更内容。期間と操作の種類で絞り込む |

操作の結果（保存・失敗）はトーストで知らせる。
