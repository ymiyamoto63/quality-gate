# ダッシュボード: 設計

要件は [requirements.md](requirements.md)。画面の共通規則は [アーキテクチャ](../../architecture.md#7-画面の共通規則)。

## 1. API

`GET /api/v1/dashboard` は登録されているリポジトリごとに 1 枚のカードを返す。

| 項目 | 内容 |
| --- | --- |
| `latestRun` | 最新の判定済み Run（ブランチを問わない。最新の attempt）の判定・完全 / 部分計測・計測日時。無ければ null |
| `openCriticalCount` / `openHighCount` | 最新の Run の、解消していない**脆弱性（M-05）**の Critical / High の件数。M-08 の違反も同じ深刻度で保存するが、混ぜると脆弱性が増えたように見えるため数えない |
| `freshness` | 最終計測日時と、最後の完全計測の日時 |

並び順は **不合格 → 注意 → 合格 → 未判定**。同じ順位の中は `owner/name` の順。
リポジトリごとに最新の Run と最後の完全計測を部分インデックス（`ix_runs_latest`）で引く。集計用のテーブルは持たない。

## 2. 画面（S-01）

```
┌───────────────────────────────────────────────────────────────────┐
│ ダッシュボード                                                     │
├───────────────────────────────────────────────────────────────────┤
│ ┌───────────────────────────────────────────────────────────────┐ │
│ │ example/sample                                ■ 不合格         │ │
│ │ 2026-09-21 02:12 · 部分計測                                    │ │
│ │ 重大 1 件 ・ 高 1 件                                           │ │
│ │ 最後の完全計測: 2026-09-14 02:11                               │ │
│ │                                   詳細 →   トレンドを見る →    │ │
│ └───────────────────────────────────────────────────────────────┘ │
└───────────────────────────────────────────────────────────────────┘
```

| 項目 | 仕様 |
| --- | --- |
| データ取得 | `GET /api/v1/dashboard` 1 回だけ |
| 自動更新 | 60 秒間隔でポーリングする。タブが非表示の間は取得しない |
| カードの見出し | リポジトリ名から最新の Run 詳細（S-03）へ直接入れる。判定を見たあと次に知りたいのは「なぜその判定か」のため |
| 最後の完全計測 | 常に表示する。部分計測が続くと、合格が実態より良く見えるため |
| カテゴリ別の状態 | 出さない。どの指標が不合格かは詳細（S-02 / S-03）で見る |
| 空の状態 | まだ計測結果が無いことと、次に取るべき操作を示す |

不合格を先頭に並べるのは、ダッシュボードを開く目的が「問題があるか確かめること」だからである。名前順だと毎回同じ場所を目で探すことになる。
