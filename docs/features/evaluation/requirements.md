# 判定: 要件

取り込んだ成果物を正規化し、合格ライン（環境変数）に照らして指標ごと・Run 全体の合否を決める。設計は [design.md](design.md)、指標ごとの規則は [指標](../../metrics.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-02 | 開発者 | 計測を確定すると、その場で判定結果が生成される |

## 機能要件

| ID | 要件 |
| --- | --- |
| EVAL-1 | ツール固有の形式を内部の正規化モデルへ変換するアダプタ層を持つ。対応形式は [指標](../../metrics.md#1-指標の一覧) に定める |
| EVAL-2 | 違反は指標ごとに定めたキー（fingerprint）で同一性を判断する |
| EVAL-3 | 指標ごとに PASS / FAIL / ERROR / NOT_APPLICABLE を判定し、Run 全体を PASS / FAIL の 2 値で決める（ERROR は FAIL として扱う） |
| EVAL-4 | 判定結果には、しきい値・実測値・前回比・判定理由・根拠となる個別違反を含む |
| EVAL-5 | 比較元を要する指標と違反の新規 / 解消の算出のため、比較元のコミットを Run に記録し、比較対象 Run を決める |
| EVAL-6 | 判定に使った合格ラインを指標ごとに残す（環境変数を後から変えても、判定済みの根拠が分かる） |
| EVAL-7 | 判定する指標の成果物が無ければ `ERROR`（fail-closed）。判定しない指標は `QG_DISABLED_METRICS` で外す |

## 受け入れ基準

- 成果物を未提出にすると、その指標が ERROR になり Run 全体が FAIL になる
- 合格ライン内の気になる点（前回からの低下など）は合否を変えず、判定理由に書き添えられる
- 比較対象の無い初回の Run では、既存の違反が「新規」ではなく「初回」として記録される
