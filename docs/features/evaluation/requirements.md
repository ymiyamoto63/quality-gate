# 判定: 要件

取り込んだ成果物を正規化し、合格ラインに照らして指標ごと・Run 全体の合否を決める。設計は [design.md](design.md)、指標ごとの規則は [指標](../../metrics.md)。

## ユースケース

| UC | 利用者 | シナリオ |
| --- | --- | --- |
| UC-02 | Admin | 計測を確定すると、その場で判定結果が生成される |
| UC-03 | Admin | 判定の失敗（合格ラインの誤りなど）を直したあと、成果物を送り直さずに再評価する |

## 機能要件

| ID | 要件 |
| --- | --- |
| EVAL-1 | ツール固有の形式を内部の正規化モデルへ変換するアダプタ層を持つ。対応形式は [指標](../../metrics.md#1-指標の一覧) に定める |
| EVAL-2 | 違反は指標ごとに定めたキー（fingerprint）で同一性を判断する |
| EVAL-3 | 指標ごとに PASS / WARN / FAIL / SKIP / ERROR / NOT_APPLICABLE を判定し、Run 全体を集約ルールで決める |
| EVAL-4 | 判定結果には、しきい値・実測値・前回比・判定理由・根拠となる個別違反を含む |
| EVAL-5 | 比較元を要する指標と違反の新規 / 解消の算出のため、比較元のコミットを Run に記録し、比較対象 Run を決める |
| EVAL-6 | 管理者は、成果物を送り直さずに Run を再評価できる（保存済みの成果物と、その Run とともに送られた合格ラインで判定し直す） |
| EVAL-7 | 申告されたスキップは `SKIP`、`execution.skippable_metrics` に無い指標のスキップの申告は `ERROR` とする。`SKIP` を含む Run は部分計測として完全計測と区別する |

## スキップの申告の規則

収集ランナーは PR の計測で PIT と負荷試験を実行しない。fail-closed を骨抜きにしないため、次のように限定する。

1. スキップは Run 作成時に `skippedMetrics` で明示的に申告する。申告の無い未提出は `ERROR`
2. スキップできる指標は合格ラインの `execution.skippable_metrics` に列挙したものだけ。それ以外の申告は `ERROR`
3. 部分計測であることを隠さない（Run 詳細・ダッシュボード・リリース判定で明示する）

## 受け入れ基準

- 成果物を未提出にすると、その指標が ERROR になり Run 全体が FAIL になる
- 同じ Run を再評価すると、同じ判定結果が再現される
- PR の計測（PIT と k6 をスキップ）が ERROR ではなく SKIP として記録され、部分計測と表示される。許容していない指標のスキップの申告は ERROR になる
- 比較対象の無い初回の Run では、既存の違反が「新規」ではなく「初回」として記録される
