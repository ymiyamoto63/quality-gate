# 保持期間と日次バッチ: 要件

古いデータと、途中で止まった Run を自動で片付ける。設計は [design.md](design.md)。

## 機能要件

| ID | 要件 |
| --- | --- |
| RET-1 | 保持期間を超えたデータを毎日削除する。既定は Run と指標値・違反 2 年、元の成果物 90 日、監査ログ 2 年で、環境変数で変更できる |
| RET-2 | 合格ラインの成果物は Run と同じ期間残す（再評価とリリース判定の根拠になるため） |
| RET-3 | 確定されないまま 24 時間たった Run を終端（`ABANDONED`）にする |
| RET-4 | 誤って短い保持期間を設定しても大半のデータが消えないよう、下限を下回る設定ではアプリを起動しない |

## 受け入れ基準

- 保持期間を過ぎた成果物は実体が消え、画面で「削除済み」と表示される。そのような Run は再評価できない（409）
- 収集ランナーが途中で落ちた Run が、翌日にはダッシュボードで処理中のまま見えなくなる
- 下限より短い保持期間を設定すると、起動時に理由つきで失敗する
