# 認証と認可: 要件

画面と参照 API を、許可した GitHub ユーザーだけが使えるようにする。設計は [design.md](design.md)。

## ロール

| ロール | 想定者 | できること |
| --- | --- | --- |
| Viewer | 参照だけの関係者（PO、QA など） | 全画面の閲覧と CSV の出力 |
| Admin | 開発者・運用者 | Viewer に加えて、Run の再評価、利用者とロールの管理、監査ログの閲覧 |

ロールは quality-gate 内で個別に付与し、GitHub の組織情報には依存しない。ログインできる人は、登録されているすべてのリポジトリの結果を見られる。

## 機能要件

| ID | 要件 |
| --- | --- |
| AUTH-1 | GitHub アカウントでログインする（GitHub App の user-to-server 認可フロー） |
| AUTH-2 | ログインできる GitHub ユーザーを許可リストで管理する。リストに無いユーザーと無効化されたユーザーは、GitHub の認証に成功しても拒否する |
| AUTH-3 | 利用者が 1 人もいないときだけ、最初にログインしたユーザーを Admin として登録する |
| AUTH-4 | ロールに基づく認可を API で強制する。ロールの変更と無効化は次のリクエストから効く |
| AUTH-5 | アプリを再起動してもログイン状態を保つ |

## 受け入れ基準

- 許可リストに無い GitHub ユーザーはログインできず、「管理者に登録を依頼してください」と案内される
- Viewer は再評価・利用者の管理・監査ログの API を呼べない（403）
- 管理者が利用者を無効化すると、その利用者の既存のセッションは次のリクエストで使えなくなる
