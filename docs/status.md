# 実装状況

**要件定義書の機能はすべて実装済み**（2026-09-26）。対象リポジトリの計測は、quality-gate 側の収集ランナーが対象を取得して行う
（[収集ランナーで計測する](operations/collector.md)）。

| 領域 | 状態 |
| --- | --- |
| 指標 | M-01〜M-14 の 13 指標（M-08 は欠番）。M-13 / M-14 は既定で無効 |
| 収集ランナー | 全指標を計測する。手動実行で、ブランチ・コミット・タグ・PR を指定できる。M-02（PIT）と M-03〜05（k6 の負荷試験）は PR 以外の計測で実行する。タグの計測の比較元は前のタグ |
| 判定 | 取り込みの確定（finalize）の中でその場で行い、結果を返す。管理者は再評価できる |
| 画面 | S-01〜S-06、S-08、S-09、S-11（S-07 / S-10 は欠番） |
| 設定 | 合格ラインは `collector/targets/*.gate.yml` を Git で管理し、Run ごとに送る。画面は表示のみ |
| スキーマ | Flyway V001〜V022 |

変更の経緯は [決定事項の記録](initial/03-open-questions.md)（D-1〜D-28）を参照。

## 動くもの

- Flyway による全スキーマ（V001〜V022）の適用
- Ingest API（Run 作成 / 成果物アップロード / 確定と、その場での判定）と Ingest Token（環境変数 `QG_INGEST_TOKEN` の 1 つ）による認証
- GitHub OAuth ログインと許可リストによる入口制御
- リリース判定（S-11。UC-10 / D-23）— タグかコミットを指定し、そのコミットの最新の完全計測から結論（リリース可 / 注意あり / 不可 / 判定できない）と全指標の合否を出す。指標ごとに説明と基準の根拠（外部基準 / 業界の目安 / チーム判断）を示し、CSV を証跡として出力する（出力は監査ログに残る）。比較元のコミットも示す。タグは、収集ランナーが計測時に送ったタグでコミットに解決する
- 可観測性 — JSON 構造化ログ（`QG_LOG_FORMAT`）、相関 ID（`requestId` / `runId` を MDC に載せ、エラー応答の `traceId` と一致）。
  メトリクスは Spring Boot 標準のもの（`/actuator/prometheus`）だけで、独自のものは持たない
- ファイルの移動・リネームを収集ランナーが対象の履歴から求めて送り（`git-renames`）、判定のときに Run に保持して、移動しただけの
  M-07 の違反を新規・解消として扱わない（指標仕様書 0.4）
- **取り込み → 正規化 → 判定 → 読み取りモデル更新**の一連の流れ
  - M-01 ブランチカバレッジ（JaCoCo XML / lcov）
  - M-02 ミューテーションスコア（PIT `mutations.xml`）— status を数え直して仕様の式で計算し、
    実行範囲（変更範囲 / 全量）ごとに前回比とトレンドの系列を分ける。
    frontend は「未計測」ではなく「対象外」と表示する
  - M-03 応答時間 p95 / M-04 スループット / M-05 エラー率（k6 の summary JSON）— 3 回実行の中央値で判定し、
    計測環境（`environment.name`）ごとに前回比とトレンドの系列を分ける。
    シナリオ単位の p95 も判定し、エラー率 5% 超は負荷試験が成立していないとして ERROR。
    対象リポジトリは収集ランナーが k6 で計測する（PR 以外）。quality-gate 自身の性能は計測しない（D-17）
  - M-06 重大・高 脆弱性件数（SARIF）
  - M-07 循環的複雑度 15 超の新規関数数（PMD XML / ESLint の JSON）— 比較元は base スコープの解析結果、
    無ければ比較元コミットで判定済みの過去の Run。収集ランナーは frontend も quality-gate 側の ESLint の設定で解析する
  - M-09 OpenAPI の破壊的変更件数（oasdiff の JSON）— level 3 を破壊的変更として数え、level 2 は WARN。
    比較元に OpenAPI 定義が無い新規 API は「対象外」
  - M-10 アクセシビリティ違反（axe-core の結果 JSON）— WCAG 2.2 AA の基準に含まれるルールの
    critical + serious を数え、設定の `pages` の画面がすべて検査されているかを確かめる。
    Run 詳細には「重大 0 件は適合の十分条件ではない」と常に注記する
  - M-11 テスト成功率（すべてのテストの JUnit XML。`test-junit-xml`）— `<testcase>` を数え直し、コンポーネントごとに判定する。
    実行 0 件は「すべて成功」ではなく ERROR、再実行での成功は WARN
  - M-12 スキップされたテスト数（M-11 と同じ成果物）— 比較対象 Run からの増加を判定する（既定は 1 件でも増えれば FAIL）。
    M-11 / M-12 は既定で有効
  - M-13 シークレット検出件数（Trivy の SARIF。メタデータ `scanners` に `secret`）— 検出されたものすべてを数える。
    走査した対象を申告した SARIF では、シークレットを M-06 から分ける
  - M-14 ライセンス違反件数（Trivy の SARIF。メタデータ `scanners` に `license`）— パッケージ単位で最も緩いライセンスを採り、
    forbidden は FAIL、restricted・分類不明は WARN。M-13 / M-14 は既定では無効（設定の `secrets` / `licenses`）
  - 差分算出（新規 / 継続 / 解消 / 初回）、スキップ申告、fail-closed
- **再評価** — 管理者が Run ごとに実行できる。保存済みの成果物と、その Run とともに送られた設定で、その場で判定し直す
- **日次バッチ**（`@Scheduled`）— 保持期間を過ぎた成果物・Run・孤児ファイル・監査ログの削除と、
  finalize されない Run の `ABANDONED` 化（時刻は `quality-gate.schedule.*`）
- **監査ログ** — 利用者・リポジトリ・再評価・保持期間の変更と、リリース判定の CSV 出力を追記のみで記録
- **管理画面** — リポジトリの登録と有効 / 無効（S-08）、
  許可リストとロール・監査ログ・保持期間（S-09）、設定の表示（S-06）、
  リポジトリ詳細（S-02）
- **設定解決** — 収集ランナーが送る設定ファイルを行番号つきで検証し、
  内容ハッシュで版管理して Run に紐づける。設定ファイルは収集ランナーが `collector/targets/*.gate.yml` を Run ごとに送る。ファイルの無い古い Run は前回の判定で使った版で判定し直す
- **収集ランナー** — quality-gate の GitHub Actions（セルフホストランナー）で対象リポジトリを取得・計測・送信する。
  計測は手動実行（`workflow_dispatch`）で、対象とブランチ・コミット・タグ・PR を指定する。対象のコードは計測用のコンテナの中で動かす
- **Run 詳細（S-03）と違反一覧（S-04）** — 判定結果をカテゴリ別に読み、
  違反を状態・深刻度で絞り込み、GitHub の該当箇所へ辿れる
  - `GET /api/v1/runs/{runId}` / `GET /api/v1/runs/{runId}/findings` / `GET /api/v1/runs`
  - 合格ライン・前回比・判定理由・スキップ申告の表示
  - 処理失敗（`FAILED`）は判定結果 `FAIL` と区別し、対処方法を添えて表示
- **トレンド（S-05）** — 指標の時系列をコンポーネント / 計測環境ごとの系列で表示
  - `GET /api/v1/repositories/{id}/trends`
  - 未計測は線を途切れさせて描き、0 を打たない（FR-08-6）
  - しきい値を重畳表示し、期間内で変わっていればその旨を示す
  - グラフはインライン SVG（canvas ではないため中身を読み上げられる）
- ダッシュボード API（`/api/v1/dashboard`）と `/api/v1/me`
- SPA を同梱した同一オリジン配信
- OpenAPI の生成 → フロントエンドの型生成（必須項目と null 許容まで宣言）
- quality-gate 自身のアクセシビリティの自動検査（axe-core、ライト / ダーク両モード。Pull Request の CI）

## 実装しないと決めたもの

経緯と理由は [決定事項の記録](initial/03-open-questions.md) を参照。

| 機能 | 決定 |
| --- | --- |
| 必須チェック化によるマージブロック | スコープ外（D-4） |
| 対象の CI から送る経路（action / CLI）、ランナー種別、Check Run の出力 | 削除（D-19） |

| 免除、通知、定期実行、日次再評価、計測途絶の警告 | 削除（D-22）。判定から外したいものは合格ラインの `exclusions`・`enabled`・しきい値で扱う |
| コンポーネントの DB・画面での定義、M-08 API 契約テスト成功率 | 削除（D-25） |

| ジョブキュー、リポジトリごとの Ingest Token | 削除（D-27） |
